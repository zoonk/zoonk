# The app frame and gated pages

Which pages live inside the one frame, what the frame may depend on, and what a page that needs an account shows.

- Every app page (the tabs and the pages they open, the mock choosers, statistics, settings, the catalog with `b/**`, and onboarding with `start/**` and the focus test) lives under `apps/main/src/app/[lang]/(app)/`, whose one layout draws the frame (sidebar, bars, tab bar), so navigating never remounts it. Only the player's screens, where the learner does the work (a lesson, a session, a running mock, a challenge, a call…), and the public marketing pages sit outside it with their own layout. The router keeps visited pages hidden in the document, so frame styles must not depend on the page inside (no `:has()` on page content). The exceptions are the first-paint fallbacks in `learn-tab-navigation.tsx`: `TabRootOnly`'s hides its copy of the top bar on a page with its own bar, and the tab bar's hides on an onboarding screen (onboarding has no tab bar); they exist only before the router has kept any other page. A client component in that frame that reads the pathname (a current-page mark) gets its own `Suspense` whose fallback draws the same UI unmarked: a dynamic route's pathname is only known at request time. The frame draws the learner (`useFrameLearner`) from what its section's layout reads in the same server render: every section under `(app)` answers it, a private one with `LearnerSummarySeed` and the static catalog with `<ProvideLearnerSeed seed={null} />`, or the frame waits for an answer that never comes.
- Pages don't redirect on the session. A page that needs an account keeps its header and shows the gate under it (`AuthGatePage` in `apps/main/src/components/auth-gate.tsx`; `LearnNoGoal` for a page that needs a goal); a task screen outside the frame shows `AuthGateScreen`. The home page's redirect for anyone with a session runs in `proxy.ts` after locale detection, before rendering. Under Cache Components a `redirect()` after the static shell reaches the browser as a client-side redirect, and `export const instant = false` (which would block the route) is not used.
