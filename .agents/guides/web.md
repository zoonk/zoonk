# Web UI and localization

This guidance applies to React and Next.js UI across apps and shared packages, including `packages/ui`, `packages/player`, and React leaves in `packages/core`. Native Apple and Android UI follow their platform instructions.

## Components and routing

- Prefer Server Components and server data fetching. Add client state for browser interactions; use effects for synchronization with external systems. When deciding whether an effect is necessary, consult [React's effect guidance](https://react.dev/learn/you-might-not-need-an-effect) and the relevant [React best practices](../skills/vercel-react-best-practices/SKILL.md).
- Use `Suspense` with a loading skeleton built from `@zoonk/ui/components/skeleton`, colocated with the component it represents and drawn in the final layout's shapes, with the page's static words (its title, section labels) drawn for real, so nothing moves when the content arrives. A word in a skeleton must come from the catalog the loaded page uses (main's and learn's can translate it differently); otherwise draw a bar. Client navigations should paint from the prefetch with no skeleton.
- Links to app pages prefetch in full (`LearnLink` and `ListRowLink` do by default; main's `Link` takes `prefetch`), so pages whose content depends on their URL paint at once. Opt out only for a destination that does something when opened (`prefetch={false}` for practice, which picks a fresh set; `prefetch="auto"` for a lesson that may still need writing).
- Every app page (the tabs and the pages they open, the mock choosers, statistics, settings, the catalog with `b/**`, and onboarding with `start/**`) lives under `apps/main/src/app/[lang]/(app)/`, whose one layout draws the frame (sidebar, bars, tab bar), so navigating never remounts it. Only the player's screens, where the learner does the work (a lesson, a session, a running mock, a challenge, a call, the focus test…), and the public marketing pages sit outside it with their own layout. The router keeps visited pages hidden in the document, so frame styles must not depend on the page inside (no `:has()` on page content). The exceptions are the first-paint fallbacks in `learn-tab-navigation.tsx`: `TabRootOnly`'s hides its copy of the top bar on a page with its own bar, and the tab bar's hides on an onboarding screen (onboarding has no tab bar); they exist only before the router has kept any other page. A client component in that frame that reads the pathname (a current-page mark) gets its own `Suspense` whose fallback draws the same UI unmarked: a dynamic route's pathname is only known at request time.
- Pages don't redirect on the session. A page that needs an account keeps its header and shows the gate under it (`AuthGatePage` in `apps/main/src/components/auth-gate.tsx`; `LearnNoGoal` for a page that needs a goal); a task screen outside the frame shows `AuthGateScreen`. The home page's redirect for anyone with a session runs in `proxy.ts` after locale detection, before rendering. Under Cache Components a `redirect()` after the static shell reaches the browser as a client-side redirect, and `export const instant = false` (which would block the route) is not used.
- Use [zoonk-compound-components](../skills/zoonk-compound-components/SKILL.md) when creating or refactoring reusable React UI, and [zoonk-design](../skills/zoonk-design/SKILL.md) for visual or interaction decisions. Keep domain compositions free to assemble these primitives.
- Define repeated accessibility IDs once as `*_ID` constants, shared across files when necessary.
- Preserve Next.js typed routes with literal hrefs or `as const`; never cast values to `Route`. Custom link wrappers should use a generic `Route<Href> | URL` prop.
- Use `ClientLink` when a Base UI `render` prop requires a client component.
- In `apps/main` pages whose only dynamic segment is `[lang]`, read the locale with `lang()` from `next/root-params` instead of awaiting `params`. Next.js warms prefetched session shells with `params` still pending but resolves them in the final render, so cached reads after `await params` log "Unexpected cache miss after cache warming".

## Localization

- Use `getExtracted` on the server and `useExtracted` on the client. Call the returned `t` with string literals; do not use translation keys or pass translation functions through props or helpers.
- Translate copy in the component that owns it. Do not hoist cheap translation lookups or pass labels solely to avoid repeated calls. Caller-provided copy may be an intentional reusable API.
- Use one ICU plural message, such as `{count, plural, one {# item} other {# items}}`, instead of singular/plural branches. A count that can be zero also gets `=0` (`{count, plural, =0 {# items} one {# item} other {# items}}`): Portuguese and French put 0 in `one`, and Portuguese says "0 aulas". Follow the [copy styleguide](../../packages/i18n/.eloqnt/styleguide.md) for user-facing text, including its voice, honest-progress, and feature-name rules.
- When source copy changes, extract through the affected app's dev server or build, translate with `pnpm --filter <app> i18n` (`eloqnt translate`), and run its `i18n:lint`. After translation, reviewed translation text may be corrected by hand; put recurring corrections in the shared Eloqnt style guides. Never hand-edit PO structure, IDs, references, or headers. Unrelated tasks do not need extraction or translation runs.
- In `apps/main`, client components receive only their route's messages (`ClientMessagesProvider` in `apps/main/src/i18n/client-messages-provider.tsx`): every page gets main's catalog and learn's site namespaces (`learnSiteMessages`: what public pages render too, such as feedback, the belts, the goal switcher and the buddy names), the `(app)` frame adds the learn catalog (`scope="learn"`) to every app page, and screens that render the player's components add the player catalog (`scope="player"`). Wrap the part that needs a scope in `ClientMessagesProvider`: a route's `layout.tsx`, or the page itself inside the frame (the buddy tab, a subject's or a chapter's "Ask").
