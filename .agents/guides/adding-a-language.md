# Adding a language

Every supported language ships with the same product, copy, and content quality. Work through this checklist before the language is visible to learners.

1. **Supported locale.** Add the code to `SUPPORTED_LOCALES` and its native name to `LOCALE_LABELS` in [locale.ts](../../packages/utils/src/locale.ts). Web routes, the sitemap, and Android catalogs read this list, and `pnpm typecheck` flags every other `Record<SupportedLocale, …>`. Also add the language where typecheck can't see it: the Apple project's supported localizations in [project.xcproj](../../apps/apple/Zoonk.xcodeproj/project.xcproj), the [prompt language names](../../packages/ai/src/tasks/_utils/prompt-language.ts) with the regional variant courses teach, and the Stripe checkout locale overrides.
2. **Catalogs and style guide.** Write `styleguide.<code>.md` in the [Eloqnt style guides](../../packages/i18n/.eloqnt/) with its register, regional variant, the full feature glossary, and the buddy names, following the existing guides. Add an empty `<code>.po` next to `en.po` in every `messages` folder, because Eloqnt infers locales from those files. Then run `pnpm i18n` and `pnpm i18n:lint`, and confirm every web, Apple, and Android catalog has the language. Never write translations by hand.
3. **Context pack.** Write the language's pack in [language-context.ts](../../packages/ai/src/tasks/_utils/language-context.ts) for the region its prompt language name teaches: currency and number formats, common first names, cities and places, everyday life, school system and stages, national exams, and register. Writing prompts read it as `LOCAL_CONTEXT`, and typecheck flags a missing pack. Goal suggestions and examples follow the language and region, and a page never suggests learning the language it's written in.
4. **Evals.** Add a few eval cases in the language to the [eval tasks](../../apps/evals/src/tasks/), and have a native speaker spot-check the writers and classifiers. Evals focus on English and Portuguese, so these spot checks set the quality bar for other languages.
5. **Legal.** Translate the [terms of service](../../apps/main/src/app/[lang]/terms/) and [privacy policy](../../apps/main/src/app/[lang]/privacy/) into `<code>.mdx`. A person reviews them before launch.
6. **Text length.** Check the key screens in the new language, in Focus and Fun, on a phone and on desktop: onboarding, Today, a lesson, Progress, and the paywall. Look for truncation and awkward wrapping, especially in Fun's wide display type.
