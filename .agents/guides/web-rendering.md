# Web rendering: server first, shells and skeletons

What renders on the server, what a page paints first, and how a part that needs the browser is drawn. Applies to React and Next.js UI in the apps and the shared packages.

- Prefer Server Components and server data fetching. Pass a client component only what it draws: its props ride in the page's HTML twice (the payload and the client cache's copy) and in every prefetch of the page. Add client state for browser interactions; use effects for synchronization with external systems. When deciding whether an effect is necessary, consult [React's effect guidance](https://react.dev/learn/you-might-not-need-an-effect) and the relevant [React best practices](../skills/vercel-react-best-practices/SKILL.md).
- Use `Suspense` with a loading skeleton built from `@zoonk/ui/components/skeleton`, colocated with the component it represents. What a skeleton draws, and where it stops, is craft [X3](../skills/zoonk-design/references/craft.md#x3-a-state-change-moves-nothing)'s placeholder rule. A word in a skeleton must come from the catalog the loaded page uses (main's and learn's can translate it differently); otherwise draw a bar. Hard loads and taps must paint the static shell (static UI and shared cached content) immediately, with skeletons where content is still streaming. Skeletons are valid on both; blank screens, unresponsive taps and slow complete loads are failures. Never hold first paint to hide a skeleton. Keep private cached prefetches: they make the learner’s content available before a tap without delaying the shell. On a hard load React shows streamed content in the first paint only when it arrived before it; otherwise it waits at least 300 ms after the shell painted. So the shell is what learners see for that long: draw it as the page as far as X3 lets it (its words, never an empty column), keep content that arrives together in one boundary, and keep what the page sends ahead of its content small. Shared content comes from shared `"use cache"` reads, so it joins the shell; the learner's own reads stay `"use cache: private"` functions (`packages/core/AGENTS.md`) inside small holes.
- A part that only draws in the browser calls `use(browser())` (from `react-dom`) inside its own `Suspense`, whose fallback is its skeleton: the server sends the skeleton and the browser draws the part as the page hydrates, with no second render after hydration. Keep `useIsMounted` for what changes once a server-drawn page has hydrated, such as a control enabled then, and `useSyncExternalStore` with a server default for a browser value the server can guess.
- In `apps/main` pages whose only dynamic segment is `[lang]`, read the locale with `lang()` from `next/root-params` instead of awaiting `params`. Next.js warms prefetched session shells with `params` still pending but resolves them in the final render, so cached reads after `await params` log "Unexpected cache miss after cache warming".
