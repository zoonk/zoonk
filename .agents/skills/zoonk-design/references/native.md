# iOS and Android

Native apps are Zoonk's design inside native components, so a learner who switches phones finds the same app. The content layer is the same on web, iOS and Android, from one source: colors, type roles, radii, list and row anatomy, page structure, marks, meters, characters and moments. `globals.css` generates each app's palette and radii in every mode, each app holds main's type roles once (Geist and Geist Mono), and each builds main's shared pieces once (the page header, section titles, lists and rows, buttons, panels, meters, task segments, readouts, goal rings, chips, answer options and their feedback, fields, the goal box), so screens use roles and pieces, never a hex value, a size or a radius of their own. The chrome layer stays the platform's, tinted with Zoonk's ink and never repainted: navigation containers and bars, tab bars and rails, toolbars, sheets, alerts, menus, pickers, text editing, gestures, Liquid Glass and Material's containers. That keeps what the OS gives for free: resizing, font scaling, Bold Text, more contrast, dark mode, screen readers and new devices. Icons stay each platform's set (SF Symbols, Material Symbols), the closest match to main's. The class names and pixel sizes in the [design skill](../SKILL.md#zoonks-visual-language) are the web's; the [Apple](../../apple-human-interface-guidelines/SKILL.md) and [Android](../../android-material-guidelines/SKILL.md) skills map each one to its native role and piece.

The [craft](craft.md) rules hold in both apps, and the craft read runs on simulator and emulator screenshots the same way, with this split:

- **The platform's.** System bars, tab bars, toolbars, sheets and menus keep their own insets, item sizes, icon sizes and corner shapes. Never nudge a toolbar item to line up with the content under it, and don't report one that doesn't.
- **Ours, in the content.** One start edge and one end edge per column, from the page's shared container (`ZoonkList` on iOS, the page's scaffold and `ListRow` on Android), never from padding on a screen. Marks on one axis and labels on one edge in a list. Space, radii and sizes only from the shared pieces, the type roles and the generated radii, so a screen has no number of its own. Controls on one row share a height, and a filled and an outline button look one size.
- **Targets.** 44pt to press on iOS and 48dp on Android, whatever the control looks like.
- **Icons.** An SF Symbol takes the role and weight of the text beside it; Material Symbols stay Outlined at weight 400. Icons side by side are one size and one weight, and one thing has one symbol across the app.
- **Text sizes.** Dynamic Type and font scale change every size, so check edges and each row's line at the default size and at a large one: what was side by side stacks, and still starts on the column's edge.
- **Roles.** The [role table](../SKILL.md#find-the-piece-before-you-build-one) holds in both apps, each role drawn by the platform's own piece (the system's back button and sheets, a bottom bar for the main action); the [Apple](../../apple-human-interface-guidelines/SKILL.md#roles) and [Android](../../android-material-guidelines/SKILL.md#roles) skills say which.
