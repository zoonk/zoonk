# The picture gate

The PR's pictures pass `pnpm pr:media check` before the body goes up ([when](../../zoonk-pull-request/references/pictures.md)). It holds every picture to its capture record, so a reviewer sees the build the PR ships, read by someone who didn't make it:

- **Captured.** Each picture in the body has a record with its bytes: from `pnpm pr:capture`, an Apple layout capture, an adopted native render, or a registration. Adopt measured Apple or Android renders with `pnpm pr:media adopt <before|after> <render.json>...`, using each picture's layout file from the Apple screenshot test or an Android render with `-Pzoonk.shots`. Register an existing before picture (taken on the base, or kept from an earlier capture) with `pnpm pr:media before --platform <web|android|apple> --source "<where it came from>" <files>`; it passes, since an old before is expected. It refuses an after. A picture only a booted simulator or emulator can show is taken by `pnpm pr:media device --platform <android|apple> --device <udid|serial> --name "<what it shows>"`. Open the app with `agent-device` first. In T3 Code pass the executable path returned by the Device panel as `--agent-device <command>`. Nothing measures its layout, so the body shows it only in the section `pnpm pr:media device-section <pictures>...` writes for the device pictures named, in order, and `pnpm pr:media check` compares that section with the body byte for byte: run it and paste what it prints as it is, between blank lines, and never write or edit the section by hand. That section is the heading `## On a device (layout not measured)` and a table of the pictures, each with what it shows and what was verified (the device, and the build's commit, or for an emulator "build not verified, installed <time>"). Any other native after picture with no capture behind it is registered with `pnpm pr:media pending --platform <android|apple> <files>`. It fails the check as pending, and the handoff names it as unverified.
- **Current.** An after picture fails when its build is unknown, has uncommitted changes, or is older than a later commit to its app or `packages/`, on every platform: an Android render's and an Apple Debug build's stamps count the same way as the web's build. Changes to files `.gitattributes` marks `never-on-screen`, such as E2E specs and unit tests, don't count; test code that draws pictures (Android screenshot tests, Apple captures) does. Commit, rebuild and capture again, also after each push. A picture whose pixels didn't change keeps its read, and a changed one keeps the read it retakes, so its next read checks only the fixes.
- **Read.** `pnpm pr:media tiles` cuts each after picture still to read into original-size tiles and writes `tmp/pr-media/read/READ.md`, the reader's sheet. Give it to an agent that built none of the screens, on a design model ([pick the model](../../../guides/orchestration.md#pick-the-model)). It reads every screen and tile blind before any numbers, then opens the before pictures to [sort each finding](../../zoonk-design/references/craft.md#a-finding). Record the read with `pnpm pr:media read --by "<who read>" --findings <file.json>`, a JSON array of `{ "file", "text", "rule", "before", "misleads" }` with files as READ.md lists them, or without `--findings` for a clean read.
- **Resolved.** Any finding the picture disproves closes with `pnpm pr:media resolve <id> --not-a-fault "<why>"`. One the before picture doesn't show that misleads a learner or breaks a named rule otherwise stays open until `--fixed <commit>` and a picture retaken from that commit, or `--exception "<who granted it>"` for one the user granted. Any other, a misleading one main already shows included, closes with `--issue <number>`. The body shows what `pnpm pr:media closed` prints, for the user to accept or overrule.
- **Measured.** The check judges each folder's captures itself, on every platform, and fails an after side on a failing relationship, a part it couldn't measure, or a missing scenario; a failure the base has too closes with its issue in [`EXCEPTIONS`](../../verify/references/pages.md#alignment). A before side isn't judged. The summary's `layout measured with nothing declared on N screens` names screens with no declared piece, and `layout not measured for N captures` names after captures with no alignment report: the read alone checked their layout.

The gate checks every after capture in the manifests above the body's pictures and under `tmp/pr-media`, even if the body shows only a few. Pass `--manifests <folder>` for each additional capture root.

Right after `pnpm pr:capture after`, the check fails on "no read" and `media.md` isn't written: that's expected. It appears once the read is recorded and the check passes. CI doesn't run the check, and it can't see a picture that measures right and looks wrong: the read catches that.
