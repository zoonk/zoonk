# A Vercel preview for the user to try

A bigger UX change that the user should try by hand (a new flow, a reworked screen, an interaction the screenshots and video can't settle) gets a Vercel preview as the very last step: once every check passes and every comment is resolved, since a later push leaves it behind. A small UI change, or one with nothing to see, gets none; its screenshots are enough. A blog post gets one sooner, for its PR body ([show the change](../../zoonk-commit/references/show-the-change.md)). Start it with `pnpm preview`, which deploys only the apps the PR changes ([preview behavior](../../../../.github/DEPLOYMENTS.md#preview-behavior)) and prints its run's URL, and wait for that run to deploy before you hand back: `gh run watch <run id> --exit-status` waits for it, and `gh run view <run id> --log | grep -E ' (main|api|admin|blog): https://'` prints its URLs. A run listed by branch can be an earlier preview. A failed preview is investigated like a failing check.
