# Screen coverage

Step 7 of [verify](../SKILL.md), before a PR that changes what a learner sees: every screen the branch touches is pictured and read once by eyes that built none of it. The steps above read what the builder chose to look at; this one reads the rest.

1. **List the screens.** Every screen and state the branch changes, and every screen that imports a shared piece it changed (follow the imports, not the pixels that moved), on each platform the change reaches. A row is a place a person can land: a state, its error, its empty, its limit and its wait included.
2. **Picture them on the production build,** at the sizes, languages and windows where layouts break:

   | Platform | Pictured at                                                                                                                                                                                                              | With                                                                                                                                                                                                                                                                                                               |
   | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
   | Web      | 390 and 1440, in English and Portuguese (`/pt/…`, as a `pnpm dev:persona … --locale pt` learner); dark too for tab roots, overlays and an error page. Internal tools also at 390 on their home, a list and a detail page | `pnpm start`, then `pnpm pr:capture after <paths> --email <learner> --viewports phone,laptop --out <folder>` (`--steps` for a state behind taps, `--app` for another app, `--schemes light,dark`), and `pnpm verify:scenarios` for the named states                                                                |
   | Apple    | iPhone and iPad in portrait; the tab roots also on iPad in landscape and on iPhone at the largest text size                                                                                                              | The [layout capture](apple-layout-capture.md) (`node apps/apple/scripts/layout-capture.mts … --side after --out <folder>`) from a Debug build of the committed head                                                                                                                                                |
   | Android  | Phone, medium and expanded windows, and a book posture where the screen has panes                                                                                                                                        | The screens' render tests with the [layout capture](android-renders.md#layout-capture) (`./gradlew <module>:testDebugUnitTest --tests '*Screenshots*' --rerun -Pzoonk.shots=<folder>`), adopted with `pnpm pr:media adopt after --to <folder> <render.json>...`; a sheet over its page from `pnpm pr:media device` |

   No model or live call: reach a state with seeded learners, fixtures or a faked run, and list a row nothing can reach without one, with why. Look at each picture before counting its row: a step that lands on the wrong screen still makes a picture. Run `pnpm verify:alignment <folder>` on every folder and fix what fails before the read.

3. **Read them blind, once.** When the screens are final, rename them to neutral numbers in the order a learner meets them and keep the map back. Readers that built none of it, on a design model ([pick the model](../../../guides/models.md)), get the numbered pictures and zoonk-design's [independent picture review](../../zoonk-design/references/craft.md#independent-picture-review), and nothing else: not the code, the diff, the spec, the before pictures or what a screen is meant to show. Give one reader a whole flow on every platform it reaches, and run the [role read](../../zoonk-design/references/craft.md#the-role-read) across areas for the roles the change reaches. Then the same reader gets the before pictures and [sorts its findings](../../zoonk-design/references/craft.md#a-finding). `pnpm pr:media read` records every picture still unread, so record all readers at once: every reader's findings in one file, with `--by` naming them all.
4. **Check each report** against the rules (craft's [deliberate choices](../../zoonk-design/references/craft.md#deliberate-choices) and the [exceptions the user granted](../../zoonk-design/references/craft.md#exceptions-the-user-granted)) and, for anything it says it saw, against the picture. Each finding is confirmed, plausible (the picture alone doesn't settle it: check it in the running app), a fault of the capture or the seed, or not a finding, with the rule that says so.
5. **Fix what blocks, file the rest.** A finding blocks the PR when it misleads a learner, whoever brought it, or breaks a named rule where the before picture didn't and the builder listed no [departure](../../../guides/exceptions.md) for it. Group those by cause (a shared piece, a formatter, a seed, one screen's layout), and check a fault seen on one platform on the other two. File the rest in an open issue that shares the fix, or one new grouped issue ([zoonk-github-issues](../../zoonk-github-issues/SKILL.md)).
6. **Close each finding with `pnpm pr:media resolve`** ([the picture gate](../../zoonk-commit/references/picture-gate.md)): a blocking one by its fix or an exception the user granted, any other by its issue or as not a fault, with why. The builder's own read never closes one. A reader of each retaken picture then answers only whether its fixes held and nothing got worse. Stop there: if that fails, reframe ([when progress stalls](../../../../AGENTS.md#principles)) instead of a third round. When a shared piece changes after the read, retake every screen that imports it.

The PR still shows only the few pictures that make the change clear, through the [picture gate](../../zoonk-commit/references/picture-gate.md); the verification section reports coverage of the remaining screens.
