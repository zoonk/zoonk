# Grow the loop

Read this when a person, or you, catches the same fault on several screens, or when a blocking cause got through [verify](../SKILL.md). The goal is that the next agent finds it without being told.

When a person (or you) catches the same thing on several screens, first look for the instruction that asked for it: a pattern, a style-guide row or a rule that the screens followed. Fix that, then the screens. Then make the catch something the next agent measures: a rule in `scripts/verify/rules/`, a check in `scripts/verify/checks.mts`, a measurement in `scripts/verify/measure.mts` (each with its unit test), or a line in a reviewer's checklist. An alignment fault goes into the relationship table (`scripts/verify/alignment-table.mts`) when a rule can state it: name the parts, declare the relationship, and add the real capture of the fault and of its fix to `alignment-cases.json` with a test that fails the first and passes the second. When no rule can state it, it becomes a question in craft's [craft read](../../zoonk-design/references/craft.md#the-craft-read). Add a check when a rule can state the fault: a check guards against it coming back. It never defines a good screen, so a fault only eyes can judge becomes a reader's question instead. When a review finds an input that breaks a pure function, the fix adds a property test over that kind of input ([zoonk-testing](../../zoonk-testing/SKILL.md)), not only the one example.

A blocking cause from the [screen coverage](screen-coverage.md) that a measurement or a lint could have caught ends in one of these in the PR; any other puts the idea in its issue, by why it got through:

- **No run reached the state** (a failure, a limit, a paused goal, a row left open): it becomes a scenario in `scripts/verify/scenarios/`, with the seed that puts a learner there, so `verify:scenarios` and the read both reach it next time ([scenarios](pages.md#scenarios)).
- **No check measured the relationship:** a relationship in the [alignment check](pages.md#alignment), declared on its piece or held on [every page](pages.md#page-rules), with a failing capture first. A line that ends on a separator, one word alone on a wrapped title, facts line or button, two control heights in one row, content cut or scrolled with no sign of it, and a helper as large as its title are measured this way. A capture records which measurements it took, so a new rule also marks older captures not measured until they're retaken.
- **One value written two ways** (a date, a duration, a range, a count): one formatting module per platform, held by a lint ([checks on the source](pages.md#checks-on-the-source)), so a screen can't write its own.
- **Only eyes can judge it:** a role drawn two ways across areas or platforms, a word a newcomer can't know, one thing or one action named two ways, a sentence that reads wrong. The [role read](../../zoonk-design/references/craft.md#the-role-read) and the [independent picture review](../../zoonk-design/references/craft.md#independent-picture-review) ask these, so a question that would have caught it goes there.
