# Measuring pages

`pnpm verify:pages` (`scripts/verify/`) loads each path fresh, waits until the page stops changing, and measures it on six screens: `phone` (390), `tablet` (820), `tablet-landscape` (1180), `laptop` (1440), `desktop` (1920) and `wide` (2560), the first three with touch. Each screen is loaded in the first color scheme and then switched to the others in place, since dark mode is the device's `prefers-color-scheme` in CSS alone. It exits with 1 when anything fails.

## Run it

| Where                      | Command                                                                        |
| -------------------------- | ------------------------------------------------------------------------------ |
| `pnpm start`               | `pnpm verify:pages --email <persona>@zoonk.test /today /plan`                  |
| Speed work on `pnpm start` | `pnpm verify:pages --email <persona>@zoonk.test --throttle --nav /today /plan` |
| A page anyone can open     | Leave out `--email`                                                            |
| Another checkout's server  | `pnpm verify:pages --checkout <its path> --email <persona>@zoonk.test /today`  |

It measures this checkout's Main at its Portless URL, whether `pnpm start` or `pnpm dev` serves it, and signs in with the newest code the dev mailbox received for `--email`. `--app api` or `--app admin` measures that app the same way and signs in at its own auth routes, such as `pnpm verify:pages --app api --email <address> /auth/en/setup`; `--url` points it at the app served elsewhere. `--checkout <path>` measures what another checkout serves (its app and mailbox at that checkout's Portless URLs, and its build's action names), so a branch without a check, such as a prototype, is measured by this checkout's scripts while its own `pnpm start` runs.

- `--throttle` is a mid-range phone on slow 4G (4× CPU, 150 ms, 1.6 Mbps), as Lighthouse's mobile run. Use it on production builds; it's what "instant on slower devices" means. A throttled phone hydrates seconds after its first paint, so a bug that needs a fast hydration (a script and React racing for the same element) shows only without it: run `--nav` once unthrottled too.
- `--nav` loads the first path, then taps the visible link to each next path in order, as a learner moves between them (on the phone and the laptop). `navigations/paints.png` shows every paint after each tap: what the learner saw, not only when the URL changed.
- `--nav --no-prefetch` blocks the next pages' prefetches, so each tap waits on the network, and `--nav --early` taps each link right after a cold load showed its content, before the page's code is ready (a learner opening the app on a slow phone and tapping at once; a tap before hydration reloads the whole page). Run each once for a change to loads, links or prefetching: they're the bad days a prefetched walk never shows.
- `--baseline <folder of an earlier run>` compares each page's medians (LCP, FCP, blocking time, CLS, server CPU, JS) and words with that run's, and puts its screenshots beside the new ones in the contact sheets. Save a run before you change a page. To measure the base in this checkout, check it out on a temporary branch whose last path segment matches this branch's (`measure-base/<segment>`): Portless names the URLs after it, and a detached HEAD serves under another checkout's names.
- `--intruder <another learner's email>` also opens every path as that learner. With `--email`, every path is opened signed out too; neither may receive the learner's email, account id or full name.
- `--local-storage <name>=<value>` (repeatable) sets what the page keeps on the device before every load, such as `sidebar-collapsed=true` for the collapsed sidebar.
- `--soak <laps>` walks the paths that many times in one tab, by their links (one path reloads), and compares the browser's heap, DOM nodes and listeners after a forced garbage collection, and the server's memory, after the first lap and the last.
- `--queries <file>` reads the statements the server logs when it was started with `ZOONK_QUERY_LOG=<that file>` (`ZOONK_QUERY_LOG=$PWD/tmp/verify/queries.jsonl pnpm start`; SQL, time and row counts, never parameters). Compare database time and repeated reads between runs, not statement counts: many quick statements are fine. Database time swings with whatever else uses Postgres, so compare it back to back on a quiet machine. Each page is also rendered once on its own, so its statements aren't mixed with prefetches, and each read's plan is checked for filters no index serves. The loads table adds each load's statements and database time.
- `--viewports phone,laptop` and `--schemes light` narrow a run while you fix something; run every screen once at the end.
- `--out <dir>` picks the output folder; it defaults to `tmp/verify/<time>` in the checkout (ignored by git).
- The seed's personas (such as `v2-stocks@zoonk.test`, in `packages/db/src/prisma/seed/learners/personas`) are shared: only read with them. Walks that change a learner's state use your own `pnpm dev:persona` copy.

Each run writes `report.md` (findings grouped across screens, then a row per load and per navigation) and `report.json` (everything measured, every request included). Per page it saves two contact sheets, `screens.png` (every screen in each scheme) and `paints.png` (every paint of each load, by its time in ms), beside the full-page screenshots and each screen's `-frames` folder. A full-page screenshot draws fixed bars, such as the phone's tabs, where the viewport ended; that's the screenshot, not the page.

Hard loads and taps must paint meaningful static shell UI immediately, with skeletons where content streams. Skeletons are measured, never failed. Keep private cached prefetches; never hold paint to hide loading UI. FCP measures the initial response, and **shell words** the words the first paint shows in the page's main region. **Content** is the first frame whose main region has no skeleton and nearly all the words it settles on; on a hard load it trails the shell by at least 300 ms whenever the content streams after it, React's reveal window. A tap's **response** is its first change on screen (the new page, or the link showing it waits), its **content** the same frame rule after the new URL, and **from prefetch** whether it got the page without asking the server after the tap. **Links live** is a load's first prefetch: before it, a tap reloads the whole page. Blank detection samples visible text, graphics and skeletons after FCP; inspect filmstrips too, since DOM visibility cannot prove pixel visibility.

### On GitHub

When the report says the machine was busy, measure on a runner of its own: `gh workflow run measure-pages.yml --ref <pushed branch> -f paths="/today /plan" -f email=<persona>@zoonk.test` (`-f app=api` or `-f app=admin` measures that app instead of Main). It seeds the learners, builds and measures `main` (`-f base=<ref>` picks another, `-f base=` skips it), then builds and measures the branch with `main`'s run as its `--baseline`, so before and after share one machine; the whole run takes three to five minutes. `-f flags=` replaces the default `--viewports phone,laptop --schemes light`, such as `-f flags="--throttle --nav"` for speed work. `gh run watch <run id>` waits for it; the run's summary has both reports, and `gh run download <run id>` saves them with their screenshots. The run fails only when it couldn't measure the branch: its CPU is slower than a laptop's, so read its timings against `main`'s rather than against the lines alone, and a failing check is a finding in the report.

## What it judges

Every load also reports **main-thread work**: the CPU time the page's main thread spent, read from DevTools' thread clock. A busy machine delays it but barely changes it, so it's the number to compare when timings are noisy. The report starts with the machine's load: past three runnable tasks per core, speed, memory and regression findings are marked inconclusive and stay to look at, while main-thread work, counts, bytes, errors and everything else still hold.

A **fail** is fixed, or left only with the reason in your report. A **look at** is opened and either fixed or explained. A **craft lead**, listed in the report's own "Craft leads" section, carries its rule's id and name from zoonk-design's [craft reference](../../zoonk-design/references/craft.md): fix it, or say which [deliberate choice](../../zoonk-design/references/craft.md#deliberate-choices) it is. The role and behavior checks below are listed under "Look at" or "Failing", not there. Speed, late changes and prefetching are judged only on a production build: a dev server compiles on demand, streams without prefetching, and shows loading states learners never see. The lines live in `BUDGETS` (`scripts/verify/checks.mts`); changing one is a product decision, so propose it with evidence instead of loosening it to pass.

## What it can't tell you

- **Whether the change does what it should.** It loads pages; it doesn't use them. Section 3 of the skill does.
- **Responsiveness to a real tap (INP), re-renders and Suspense boundaries.** Blocking time is the load's share; drive the interaction, then use `agent-browser` (`vitals`, `react renders start|stop`, `react suspense`), or record a Chrome DevTools performance trace.
- **Screens behind a tap**, such as dialogs, sheets, the lesson player and results. Reach them in the walk and screenshot them there.
- **Taste.** It saves the screenshots and measures some of craft; you look at every screenshot with zoonk-design's taste bar, and an agent that didn't build the screen does the [craft read](../../zoonk-design/SKILL.md#the-craft-read). Craft is measured at load in the first color scheme, plus X3's walk: states it can't reach without submitting (a save, a check that calls the server, a busy button, a lesson's answer and result, a session's end), focus rings and the rules without a check here (E4, E6, E7, E9, S3, S5, H2, H4, H5, Z2, Z4, T2 to T6, I1, I5, D1 to D4, X1, X2, R1) aren't. Z3 has only the 44 px target check, the behavior rules only what the key and panel rows above list, and I4 and I6 only [lint](#checks-on-the-source).
- **Field data.** These are lab numbers on this machine. Compare before and after on the same setup, and don't compare a loaded machine's run with a quiet one's.

## Compare shared roles

Add `--roles` to the same `verify:pages` command to save `roles/measurements.json`, role crops and one HTML/PNG comparison sheet per role and viewport under `roles/`. The roles are `page-top`, `back-link`, `bottom-bar`, `overlay`, `subscription-gate`, `empty`, `eyebrow`, `tabs` and `list-tail`, each found by its piece's `data-slot`. At phone and laptop sizes, the write-blocked state walk captures the page and each overlay it opens. Tables compare top, height, computed column gap, first SVG size and label against the most common value. Yellow cells are differences to read, not failures. A missing slot is stated explicitly; it is not evidence that the role passed. Gap and glyph measurements are CSS boxes, not ink bearings.

The sheets don't establish gate timing, a chevron's ink gap or a bar docking over tabs. The leads that read the same hooks (`E8 named back link`, `R2 main action pinned`, `R2 primary action in page`, `R3 eyebrow piece`, `R4 one subscription gate`) run on every load, with or without `--roles`; the table above has each one's line.

## Checks on the source

Some of the same rules are checked in the source, before a page is measured. `pnpm lint` fails on each of these; `.oxlintrc.json` turns a rule off only in the file that owns the piece.

| Rule                               | Fails                                                                                                                                                                                                                         |
| ---------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `zoonk/no-page-top-spacing`        | Top padding or margin (`pt-`, `py-`, `mt-`) on `Page`, `DetailLayout`, `SectionPage`, `OnboardingPage` or `PageTop`, or on the first child of one. Any other way to push a title down passes lint: `E8 page top` measures it. |
| `zoonk/no-plus-badge`              | An element named `…Badge` or `…Chip` whose whole text is "Plus". The plan's name drawn any other way is only listed by the catalog words below.                                                                               |
| `zoonk/one-glyph-button`           | A button with more than one glyph (an icon, a keycap or a spinner; a picker's down chevron isn't counted), and a left or right arrow icon in any button, link or row.                                                         |
| `zoonk/no-hand-made-fold`          | `--collapsible-panel-height` in a class, or a down or right chevron inside `CollapsibleTrigger`.                                                                                                                              |
| `zoonk/no-hand-made-panel`         | A literal `role="dialog"` or `role="alertdialog"` outside `packages/ui`. Test files are left out, and a computed role isn't read.                                                                                             |
| `zoonk/no-hand-placed-icon-button` | An icon-only `Button`, `…Link` or `…Trigger` with a negative side margin of its own.                                                                                                                                          |
| `zoonk/one-answer-option`          | A second export named `ANSWER_OPTION_CLASS`. The same classes under another name pass.                                                                                                                                        |
| `zoonk/one-question-action-bar`    | "I don't know yet" in a button or link outside `QuestionActions`.                                                                                                                                                             |
| `zoonk/shortcut-keys`              | A raw `useKeyboardCallback` or key listener outside the kit, a `closeOnEscape` switch, a literal `aria-keyshortcuts`, a `ShortcutKbd` without its `shortcut`, and a main action disabled while pending with no `busy`.        |

`pnpm verify:catalog` lists every English string, in the web's, Apple's and Android's catalogs, that pays in other words than "Subscribe", names the plan outside pricing and the subscription page, or is a "none" option; `verify:diff` asks about each one a change adds. The phrases are in `scripts/verify/rules/catalog.mts`. It fails on a match in the web's catalogs, and CI's quality job runs it; Apple's and Android's are listed only.
