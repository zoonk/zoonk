- When writing a prompt, don't use "Zoonk" (eg "You're a Zoonk tutor"). Models don't know what "Zoonk" is, and it can lead to confusion or irrelevant responses. Instead, you could use something like "You're a tutor for a learning app."
- Prompts that write learner-facing copy must never promise a pass, score, admission, certificate or job. Use "preparation" language and, for exams, an estimated score only as a range after a mock (see `packages/i18n/.eloqnt/styleguide.md`, "Honest progress").
- Every task runs its model call through `runTaskGeneration` (`startTaskGeneration` for streams, in `src/provenance/`) and returns its `provenance`: the model that actually ran (a fallback when the requested model failed, read from AI Gateway routing metadata, not `response.modelId`), prompt version, usage, cost and latency. That also sends the call to every registered sink (PostHog's `$ai_generation` event and the `ai_calls` ledger the admin app reads). Tasks accept an optional `analytics` context; callers pass the learner id, goal and content scope so cost can be summed per learner.
- Cost is priced from each call's usage with the dated price list in `src/pricing` (the gateway's list plus `price-overrides.ts`, whose `PRICE_CHANGES` holds prices a provider announced for a later day), never from the gateway's billed cost, which is zero for our own provider keys. Refresh it with `pnpm --filter @zoonk/ai prices:refresh` when a model or price changes.
- Every call's service tier comes from `chooseServiceTier` (`src/provider-options.ts`), never a literal: `flex` for work nobody needs for hours (a later day's lessons, bands the plan reaches in days, re-reads of sources, later reviews); `priority` only while a learner waits on content very likely reused (an exam's or a language's shared notice reading, graph, outlines, lessons and item bank, or a lesson other learners' goals already plan) or on a small one-off call (understanding a goal); the standard tier for everything else, interactive calls (grading, explanations, the buddy) included. A task with no `serviceTier` runs at the standard tier.
- A lesson's reviewer comes from `getLessonCheckModels` (`src/tasks/v2/quality/lesson-check-models.ts`), never a literal, and follows the same reuse signal as its tier (`loadLessonReuse` in `@zoonk/core`): Claude Sonnet 5.5 for a lesson very likely read again (an exam's, a language's, one other learners' goals already plan), Gemini 3.8 Flash for one that may serve one learner (a niche goal's shared lesson, a private course's), always from a family other than the writer's. A fixed lesson isn't reviewed again unless the fix changed what no check flagged (`getFixReach` in core); the code checks always run again.
- Keep each task's stable instructions in its system prompt and what changes per call after it: the default provider (`src/prompt-cache.ts`) marks the system prompt for Anthropic's cache and, in OpenAI's explicit mode, for OpenAI's, so per-call text never pays the cache write's premium; Google gets no marker (through the gateway it turns Google's implicit cache off) and caches prefixes of 4,096 tokens or more on its own. A conversation sends what stays the same across its messages (a goal's context) before the turns, repeats earlier turns word for word, keeps tools and thinking the same on every step, and marks its own OpenAI cache points, so each message reads the request before it from the cache (see `tasks/v2/tutor/goal-tutor-messages.ts`).
