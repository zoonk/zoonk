- When writing a prompt, don't use "Zoonk" (eg "You're a Zoonk tutor"). Models don't know what "Zoonk" is, and it can lead to confusion or irrelevant responses. Instead, you could use something like "You're a tutor for a learning app."
- A call reads only the rules that apply to it. Text for one variant (an exam, a mode, a question format, a kind of goal, a reader language) sits in `{{#name}}…{{/name}}` blocks that `selectPromptVariants` (`src/tasks/_utils/prompt-variants.ts`) keeps in place only for that variant, or in the variant's own `.prompt.md` appended when it applies. Never print "X: no" or "none" lines for a variant the call isn't. A prompt doing two jobs is two tasks, each with its own prompt, schema and eval cases.
- When a model writes a learner-language field (a title, a role, feedback) in the practiced language or a third one, name the language in that field's rule: write `{{LEARNER_LANGUAGE}}` and `{{TARGET_LANGUAGE}}` in the prompt and fill them with `fillPromptLanguages` (`src/tasks/_utils/prompt-language.ts`), since a rule that only points at a `LEARNER_LANGUAGE` input doesn't hold. Mark such a field's example as written in `{{LEARNER_LANGUAGE}}` ("landlord", written in `{{LEARNER_LANGUAGE}}`) instead of giving it in one learner's language, which models copy into other learners' fields.
- Prompts that write learner-facing copy must never promise a pass, score, admission, certificate or job. Use "preparation" language and, for exams, an estimated score only as a range after a mock (see `packages/i18n/.eloqnt/styleguide.en.md`, "Honest progress").
- Every task runs its model call through `runTaskGeneration` (`streamTaskGeneration` for streams, which starts the stream itself, in `src/provenance/`) and returns its `provenance`, which records the model that actually ran, usage and cost. A run that throws still logs the calls the provider billed, which the default provider's `billedCallMiddleware` records, so a task names its model by gateway id rather than building a model object. Tasks accept an optional `analytics` context; callers pass the learner id, goal and content scope so cost can be summed per learner.
- A task's models, including a cheaper one for a learner's own content, come from its eval, chosen as `apps/evals/AGENTS.md` ("Choosing a model") describes.
- Every task's model chain includes a model from another provider, evaluated on that task, so one provider's outage doesn't stop it. The exception is a task no other provider can serve, with the reason beside its model.
- A learner's data never reaches a provider that trains on prompts. Only a task whose prompt holds Library content and public documents alone (never a learner's words, answers, voice, files or memory) passes `libraryInput: true` to `runTaskGeneration` or `runImageTaskGeneration`; `src/data-protection.ts` decides when that lifts the gateway's no-training filter. Speech and transcription calls, and any other model taken from `zoonkGateway` directly, pass `{ gateway: NO_PROMPT_TRAINING }` themselves, and a model served only by providers that train on prompts can't be used.
- A call's cost is what our own provider key paid, from our dated price list in `src/pricing`, plus what AI Gateway debited for it, such as its search fees: price a gateway call with `computeCallCostUsd` and the `charge` from `readGatewayMetadata`. Refresh the list with `pnpm --filter @zoonk/ai prices:refresh` when a model or price changes.
- Every call's service tier comes from `chooseServiceTier` (`src/provider-options.ts`), never a literal: calls a learner waits on use priority, prepared-ahead work uses standard, and background work uses flex.
- A lesson's reviewer comes from `getLessonCheckModels` (`src/tasks/quality/lesson-check-models.ts`), never a literal, given its reuse signal from `loadLessonReuse` in `@zoonk/core`.
- Keep each task's stable instructions in its system prompt and what changes per call after it, since providers' prompt caches reuse only a shared prefix (`src/prompt-cache.ts` marks it). A conversation sends what stays the same across its messages (a goal's context) before the turns, repeats earlier turns word for word, keeps tools and thinking the same on every step, and marks its own OpenAI cache points, so each message reads the request before it from the cache (see `tasks/tutor/`).
- Check output in code before saving it, and repair in code what code can repair: replace em dashes, strip Markdown marks from a one-line name, merge a skill written twice, drop a duplicate option. Retry or run a fix pass only for flaws code can't repair (a placeholder, a wrong fact, a loop it can't break safely), and never fail a task over a repairable flaw. The pipeline and the task's eval scorer run the same validator.
- An AI failure found while testing becomes an eval case on the task that produced it (see `apps/evals/AGENTS.md`).
