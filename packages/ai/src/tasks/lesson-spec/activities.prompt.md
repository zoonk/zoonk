An activity lets the learner do what the skill does, and the app grades what they produced. For each skill, ask: when someone uses it, what do they produce, and what could the app grade? When a template in `ACTIVITY_TEMPLATES` lets the learner produce it, that's the activity. Read every template's description, which says what the learner does there and what code checks. These are common matches, not the whole list:

- writing or fixing a program: `codeRunner`, which checks what it prints; predicting how a program's variables change as it runs, line by line: `codeTracer`; querying tables: `sqlPlayground`, which checks the rows; writing a regular expression or a spreadsheet formula: `patternTester`;
- solving an equation one move at a time: `stepSolver`, or `balance`, `numberLine` or `areaModel` when the move is on an equation, a number line or a product; working with a value that depends on others (a formula, a rate, a price, a dose, a score): `formulaModel`;
- putting the steps or stages of a process in order: `processOrder`; linking causes to their effects: `causeEffectChain`; comparing two states before and after a change (a reform, an invention, a new law): `beforeAfter`; placing events in time: `timeline`; finding places: `mapExplorer`; naming the parts of one whole: `labeledDiagram`;
- pairing each term, rule, format or tool with its example or use: `matchPairs`; sorting items into the named categories the skill itself defines (physical or chemical change; competition, predation or mutualism): `categorize`. A sort into "X" or "not X", "fits" or "doesn't fit", is a set of true-or-false judgments: plan checks instead;
- finding the wrong step in a worked answer: `findError` (see below).

The learner does each skill once in practice, on the practice right after its worked example, or on a check after it's explained when it has none, and again on the application when the skill's real use is producing something a template grades (see "Screen plan"). A check whose own move is a template's (putting steps in order, placing events, labeling parts) is that activity too. Every other check stays a check, since the app also asks checks later as practice questions: recalling a fact in a situation, judging statements, deciding, spotting a mistake, working out a number to type, or saying what a short program prints. A skill no template lets the learner do has no activity. An activity counts as a check. Never add one to decorate a screen or to show data you made up.

Outside `overview`, a skill about code is used in programs, even one worded as recognizing something (a value's type, the parts of a program), so the learner practices it on a program. In a language `codeRunner`, `codeTracer` or `sqlPlayground` runs (each one's description names its languages), the learner writes or fixes code in `codeRunner` or `sqlPlayground`, or predicts how its variables change in `codeTracer`. A `codeRunner` or `sqlPlayground` brief names the line the learner writes or fixes, which is the lesson's move, and what the program prints or returns once it's right: the learner always edits code, never only runs a program that already works, and never predicts that output, which the screen shows. Only the right edit gives that output: it shows every value the brief asks the learner to write (a count, a name, a status), printed from the code the learner edits, never only its type or a count of rows, and the brief asks for nothing the output doesn't show, so a tempting mistake prints something else. Every line, value or note the brief mentions is in the starter code it describes. In a language none of them runs, the learner still works with real code: checks ask what a program prints or does, `findError` finds the wrong line in a worked answer, and `processOrder` orders a program's lines only when they have exactly one valid order; never `codeRunner` or `codeTracer`.

"Spot the AI's mistake" is a `findError` whose worked answer an AI assistant wrote. It fits a lesson whose skill is judging work an AI assistant drafts for people at their job, as in a work or career course on writing code, drafting texts, designing screens or analyzing data, when it fits that skill better than the other templates. Its brief says an AI assistant answered a realistic question from the job, and names the one plausible mistake the lesson's skill helps catch and the step it's made in. Never plan it with `EXAMS` or in a foreign language's lessons: there a wrong step to find, when the skill calls for one, is in a plain worked answer. In every `findError`, put the mistake in an early or middle step, so the steps after it build on it and the conclusion comes out wrong because of it: a mistake always in the final "So…" step teaches learners to check only the last line.
