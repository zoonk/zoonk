## Product interpretation

The primary content outcome is a small, concrete increase in capability that makes the learner want another lesson. The reusable curriculum remains complete; the learner's visible path is allowed to be short. Content length, curriculum size, lesson kind, and private ownership are separate dimensions.

The four blog posts in `apps/blog/src/app/(post)/2026/` reinforce this distinction. `future-of-education` describes confidence, everyday language, real applications, and individual goals; `education-is-broken` advocates problem-first learning and working with AI to reason rather than reproduce answers. `learning-anything` values useful feedback and durable progress. `how-zoonk-lessons-work` documents the old compulsory loop and should be updated when behavior changes, because its claim that every explanation is followed by practice will become inaccurate.

`PROBLEMS.md` initially allows Question courses 1–3 chapters, but its definition of done explicitly requires a single chapter. Implement one chapter for a Question course.

## Proposed reusable content architecture

1. **Core:** one public course, with Overview, Basic, Intermediate and Advanced curricula. Overview alone has 3–6 chapters and useful conversational understanding without formulas or specialist prerequisites. The remaining levels cover the full subject without arbitrary chapter/lesson limits. Overview is a standalone entry, not a required prerequisite before Basic.
2. **Language:** one public course with explicit A1, A2, B1, B2, C1 and C2 chapter assignments and appropriate can-do outcomes. Show plain self-assessment descriptions; offer manual level selection and later adjustment. Do not label a short placement estimate as certification. Include real social, professional, academic and media communication where it teaches language rather than a separate subject.
3. **Question:** one reusable chapter built around a narrow question, a few focused short lessons, direct answer early, concrete example, mechanism and useful consequence. No comprehensive syllabus, mandatory intro/career material, or required quiz gauntlet. Identity includes its question scope so it cannot incorrectly reuse the broad Core course.
4. **Personalized:** authenticated owner-only course with an explicit saved brief. It may use a variable-length private outline when shared chapters cannot preserve constraints. When shared content fits, personalize a path through that content instead. Private context must not enter shared outline generation, canonical-title search, public description, images, index or reusable course embeddings.

Persist genuine chapter level metadata and chapter scope. Pass format, level, intended outcome and boundaries into chapter planning and lesson generation. Daily time is stored as the learner's revisitable commitment metric: it neither limits learning nor produces pause/overrun notifications, and never reduces the shared curriculum or changes content for other learners. Prerequisite relationships must reference valid IDs and form an acyclic graph; only introduce them where they support real goal-based path selection.

For broad curricula, generate one durable outline segment per actual level so output limits do not silently truncate the full curriculum. Each current level call receives the shared course/level contracts; independent calls do not exchange generated neighboring outlines. Validate every required level and dependency contract before installation; review actual outputs for meaningful coverage and distinct depth. Persist segments idempotently so a failure regenerates only missing/failed work. Model output token limits are technical limits, not product chapter limits.

## Dynamic discovery and useful paths

Use a typed discovery result: either one next question with stable option IDs plus `Other`, or `ready` with the resolved brief and a proposed experience. Persist answered questions server-side and ask the next one only when the answer can change scope, prerequisites, examples or practical outcome. No arbitrary question-count cap; prevent repeated questions using stored question IDs and already captured facts. Learners can skip low-value preferences or accept disclosed defaults; an unknown subject or material safety/context ambiguity still needs clarification. Untrusted learner text cannot set ownership, model choice, price, public visibility, course IDs or authorization.

Examples:

- `Python for a new job`: ask what work they need to do and what they already know. If normal software work fits shared content, select reading/modifying code, debugging, working with AI agents, tests, verification and deployment as needed. Preserve fundamentals as prerequisites and an accessible complete path; do not assume memorizing syntax is the outcome.
- `Computer science fundamentals`: include algorithms, data representation, architecture and theory with practical explanation, without replacing the request with an AI tooling course.
- `Greek myths for a six-year-old`: ask about reading/listening ability and content preferences only if still unknown; generate private age-appropriate explanations rather than relabeling adult content.
- `Stripe Connect SaaS`: establish current application/knowledge and intended payment shape, then provide educational implementation/verification steps; distinguish current technical details that need retrieval from stable foundations.
- `Physics and chemistry`: detect two coequal subjects, suggest separate canonical courses and group enrollments in a Track. `Physical chemistry` remains one established field. Do not split terms merely because their title contains multiple nouns.

For reusable paths, provide the model the actual chapter IDs, level, scope, outcomes and prerequisites. The output is ordered IDs plus a short goal summary. Validate ownership, membership, uniqueness and dependency order among included chapters server-side; do not force already-known prerequisite chapters back into an advanced learner's selection. Selecting a path never duplicates a Course record or marks skipped chapters completed. Changing preferences recomputes the path while retaining durable completion. The complete curriculum remains one action away.

## Lesson and activity contracts

Plan by a distinct learner action or insight, not every noun in the domain. First exposure to a function should teach input → useful work → returned result together; an independently useful skill such as debugging a function can be another lesson. A plain name need not become a slogan: `How functions reuse a job` can orient an overview while `Function parameters and return values` suits a more technical foundation.

Target an explanation around 150–250 words or the equivalent compact script, usually 4–7 substantive screens plus a brief payoff, with a few short sentences per screen. Treat this as a generation/quality budget rather than a universal hard screen count. Typical lessons should take 1–2 minutes; verify actual player time and attention demand. If content cannot fit under four minutes, split the authored scope before publication rather than truncate generated paragraphs or silently omit required ideas.

A lesson teaches one coherent mechanism through one concrete example. Overview gives intuition first, no formulas, dense notation or technical inventories. Basic introduces formal terms only after a concrete explanation; higher levels may use necessary notation but still explain each move plainly. Include the useful payoff naturally; do not force a named-brand anchor or another recap screen when it repeats the same point. A closing claim about a named product must be true, not invented to satisfy style.

Use explanation/tutorial/vocabulary/grammar/alphabet as teaching units. Quiz and practice are optional activities anchored to their teaching unit, available through progressive disclosure at the end or from lesson details. Review remains an optional way to revisit mistakes. Keep optional activities outside required lesson count, next lesson, automatic generation warmup, completion denominator and chapter locks. Keep their answer-level accuracy, BP and activity history when attempted. Language translation/listening/reading require an intentional preference policy rather than blindly treating all language practice as optional; some are the actual learning medium.

A short quiz can use 2–4 meaningful transfer questions for one focused idea. It does not need every supported question type. Practice should be one coherent situation with the smallest number of decisions needed, without scene-setting filler or mandatory images. These pedagogical budgets are unrelated to the explicitly uncapped discovery questionnaire.

## Images, generation cost and failure behavior

Always create a chapter thumbnail job for each generated chapter, including private chapters. Thumbnails should not block the first lesson; missing jobs need durable retry so failed artwork is not forgotten. Every authored outline chapter gets a thumbnail job, including private chapters; lesson content remains lazy.

For reusable explanations, preserve a visually rich experience but make each image earn its place: visible structure, evidence, contrast, a spatial mechanism or a useful concrete example. A short lesson with two meaningful images and well-designed text/diagram/code screens is preferable to repeating decorative artwork on every tap. For private explanations, default to no raster images; allow only a demonstrated teaching need. Prefer native diagram/chart/code renderers where they communicate accurately and avoid paid raster generation. Do not generate a decorative private course cover by default.

Represent selected imagery by a stable step index/ID, not a shortened positional array. Saving an image for step 4 must never attach it to step 1. Make image jobs independently idempotent and persist successes before retries; failed non-essential artwork can recover separately without discarding a complete text lesson. Required image-based question evidence cannot be silently dropped—fall back to a valid text question or keep that activity retryable.

Centralize a generation policy derived from persisted course ownership/format. Reusable curriculum can use sol/strong models; private discovery, outline, explanation, tutorial, quiz and practice use luna with no premium fallback. Every downstream task receives the policy, including hidden image-prompt/classification calls. Track usage and image count by course/learner/workflow, and reserve quotas atomically before paid calls so concurrent starts/retries cannot bypass them.

At the user's approximate $0.008/image, 17 images cost $0.136 per explanation before any text, activity or retry cost; 100 such private explanations cost $13.60, above the stated $9 monthly revenue. Two useful images would be $0.016. These are scenario calculations from the source brief, not verified provider pricing or a revenue forecast.

The root consolidation proposes one useful illustration per reusable explanation. This is a reasonable initial cost policy if the player also uses clear typography and native visual blocks. Select the teaching step that benefits most; it need not be the closing anchor. A complete 194-chapter language thumbnail set would cost approximately $1.55 before lessons, using the same assumed image price. Generation entitlement therefore needs to cover repeated new-course outlines/thumbnails, not only lesson creation. A private course receives one thumbnail for every authored outline chapter, matching the hard requirement. At the source assumption of $0.008 each, a 13-chapter private outline costs about $0.104 in chapter images before text/lesson images.
